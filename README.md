# 柑橘食药提示发布

本仓库保存该服务的领域资料与最小事件约定，供业务团队在统一语义上继续建设。

## 已有内容

- `contracts/domain.schema.json`：领域事件的基础字段、聚合类型和事件名称。
- `data/sample.json`：可用于联调的中文样例记录。
- `src/validator.py`：只校验基础事件信封，不包含业务流程。
- `src/models.py`：柑橘活性成分、药物成分与代谢途径、相互作用证据、提示版本。
- `src/events.py`：追加式事件日志，写入前按信封约定校验。
- `src/normalization.py`：商品名、药品别名与复方组成的归一。
- `src/guidance.py`：措辞审校规则、证据等级约束与标准不确定表述。
- `src/publishing.py`：渠道版本（海报、药房屏幕、线上问答）与患者送达快照。
- `src/privacy.py`：最小必要查询与患者/药师两种视图。
- `src/service.py`：发布服务门面，串联归一、证据、审校、发布与更正。
- `tests/`：验证样例与基础约定保持一致，并覆盖上述领域规则。

## 领域边界

当前资料围绕成分归一、证据分级和提示审校整理。事件一旦被接收，其标识、发生时间和版本不应被原地改写；业务更正应产生后继记录。涉及个人、机构或商业敏感信息时，调用方只读取完成职责所必需的字段。

核心规则：

- **先归一再判断**：商品换配方、药品别名和复方组成必须先归一到有效成分；无法确认的配方返回不确定结果，绝不猜测成分。
- **证据分级**：只有人体研究或专家共识能支撑面向患者的确定性用药安全提示；细胞或动物研究只能表述为“证据有限”，不得写成个人停药或调整依据。
- **措辞红线**：提示绝不指使自行停药、换药、调量，也不推断诊断；无法确认时表达不确定并引导咨询医生或药师。
- **按影响范围换版**：证据更新后，只有实际承载受影响提示的渠道换版；患者曾收到的内容保留当时版本，更正以追加方式记录。
- **最小必要**：查询只携带归一后的成分标识与必要人群信息，员工看不到完整病历；药师可从每条提示追到证据、来源文献、适用对象与审校人，患者视图则分清一般营养知识与用药安全建议。
