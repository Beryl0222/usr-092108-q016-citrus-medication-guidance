# 柑橘食药提示发布

面向区域药学中心的食物与用药提示发布服务：把柑橘活性成分、药物成分与代谢途径、相互作用证据、风险人群、建议措辞、来源文献、审校人、有效期与渠道版本放在同一套领域语义下管理。

## 目录结构

- `contracts/domain.schema.json`：领域事件信封约定（事件类型、聚合类型、基础字段）。
- `src/domain.py`：领域模型（活性成分、暴露档案、成分、配方版本、证据、人群、提示版本）。
- `src/events.py`：追加式事件日志，事件写入后不可改写。
- `src/normalization.py`：名称归一——商品名/别名/复方组成/换配方 → 通用成分；品种+加工形态 → 柑橘暴露。
- `src/evidence.py`：证据登记与更新，更新产生后继版本，旧版本保留并标记被替代。
- `src/guidance.py`：建议措辞的审校、修订、撤回与安全措辞护栏。
- `src/publishing.py`：渠道发布、按影响范围换版、患者更正留痕。
- `src/query.py`：最少信息查询、患者/员工分角色视图、证据追溯。
- `src/service.py`：门面，把归一、证据、措辞、发布与查询串成一次咨询。
- `src/seed.py` + `data/seed.json`：联调种子数据（文献为示例引文，发布前须由审校人核实）。
- `src/validator.py`：事件信封基础校验。

## 核心流程

1. **归一**：商品名、别名、复方组成先归一到通用成分；商品换配方以配方版本留痕，按时间取用。柑橘按品种+加工形态归一到暴露档案（西柚汁含呋喃香豆素，西柚味香精饮料则不含）。无法确认的输入返回不确定结果并引导咨询，绝不猜测。
2. **证据**：证据按版本登记，含等级（人体/病例/动物/体外）、适用边界、来源文献、审校人与有效期；更新产生后继版本。
3. **措辞**：审校通过方可发布。护栏禁止指令性停药、换药、调整剂量与推断诊断的措辞；证据仅来自动物或体外研究时，措辞必须标注不确定性并引导咨询。食品建议统一使用「避免食用/饮用」，不使用「停用」。
4. **发布**：提示按渠道（海报、药房屏幕、线上问答）发布版本。证据更新后，先定位受影响提示并修订措辞，再按影响范围换版；未受影响的渠道保持原版本。
5. **更正**：患者曾收到的内容保留当时版本快照，更正以追加方式记录（`NOTICE_CORRECTED`）。
6. **查询**：只使用归一后的成分与柑橘暴露等最少信息，不接收身份、诊断或病历；员工视图同样不含任何病历字段。患者视图明确区分「用药安全建议」与「一般营养知识」；药师可从每条提示追溯到证据、文献与适用人群。
